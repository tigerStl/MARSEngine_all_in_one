## 当前状态（Step 1：后端编排框架）

- **ShellInstallerService**
  - 已实现真实的脚本执行逻辑：
    - 在工作区根目录下查找 `.tigerclawd/installers/<moduleId>.cmd|.sh`（模块级安装）。
    - 该逻辑目前仍用于 `ScenarioApplyService` 的模块安装，不与 Setup 模板直接耦合。
  - 所有 stdout/stderr 会写入 `OutputChannelLoggerService`，进而出现在 Dashboard 的 Recent Activity 中。

- **Setup 编排核心模型**
  - `src/setup/models/SetupStatus.ts`：定义整体状态和步骤状态。
  - `src/setup/models/SetupStepResult.ts`：记录单步执行结果。
  - `src/setup/models/SetupTemplateId.ts`：5 个模板的 ID 枚举。
  - `src/setup/models/SetupExecutionResult.ts`：一次模板运行的总体结果。
  - `src/setup/models/SetupExecutionContext.ts`：上下文信息（workspace、env、config、logger、state 等）。

- **Step 与 Template 定义**
  - `src/setup/steps/SetupStepDefinition.ts`：标准化的步骤定义接口（包含 required、timeoutMs、retryable、消息生成等）。
  - `src/setup/templates/SetupTemplateDefinition.ts`：模板定义接口。
  - `src/setup/templates/SetupTemplates.ts`：
    - 已定义 5 个模板：
      - `basicCoding`
      - `agentSetup`
      - `retrievalSetup`
      - `toolingSetup`
      - `fullLocal`
    - 每个模板包含若干 `requiredSteps`，每个步骤都通过 `ShellStepRunner` 调用对应脚本：
      - 脚本前缀为 stepId，例如：`basicCoding_envScan`、`agentSetup_initializeAgent` 等。
      - 默认会调用：
        - `<stepId>_run.cmd|.sh`
        - 然后调用 `<stepId>_validate.cmd|.sh` 进行事后验证（如果存在）。

- **ShellStepRunner**
  - `src/setup/services/ShellStepRunner.ts`：
    - 按 stepId 前缀解析模板目录，优先查找 `Scripts/<prefix>/<stepId>_(run|validate|rollback).cmd|.sh`（如 `Scripts/basicCoding/basicCoding_envScan_run.cmd`），不存在时回退到 `Scripts/DefaultTemplate/`。
    - 若脚本不存在：返回 `warning`，在日志中说明缺失路径（不假装成功）。
    - 若脚本存在：使用 `child_process.spawn` 执行，实时把 stdout/stderr 前缀为 `[stepId]` 写入 Logger。

- **SetupOrchestrator**
  - 接口：`src/setup/services/SetupOrchestratorService.ts`。
  - 实现：`src/setup/services/DefaultSetupOrchestratorService.ts`：
    - `runTemplate(templateId)`：
      - 读取模板定义、环境（`EnvironmentDetectionService`）、当前配置（`ConfigService`）。
      - 构造 `SetupExecutionContext`。
      - 依次执行模板的 `requiredSteps` 和 `optionalSteps`：
        - 记录每一步的 `SetupStepResult`。
        - 对失败步骤调用 `getFailureMessage`，写入日志和 warnings。
        - 若是必选步骤失败，则终止后续步骤。
      - 聚合为 `SetupExecutionResult`，写入 `StateManager` 的 `lastSetupResult` 字段。
    - 当前版本已做到：
      - 无未捕获异常（所有步骤执行包裹在 try/catch 中）。
      - 不会因为某一步失败而导致扩展崩溃。

- **状态持久化**
  - `src/state/AppState.ts` 新增：
    - `lastSetupResult?: SetupExecutionResult;`
  - `StateManager` 中通过 `update({ lastSetupResult: result })` 写入最近一次 Setup 结果（用于后续 UI 展示和 resume 能力）。

- **基础命令集成**
  - `src/extension.ts`：
    - 创建了 `DefaultSetupOrchestratorService` 实例。
    - 注册命令：
      - `tigerClawdEntry.runSetupTemplate.basicCoding`
        - 手动执行后，会运行 Basic Coding Setup 的所有步骤，并在 Recent Activity 输出对应脚本日志与总结。
    - 这一命令目前主要用于内部验证后端框架，尚未接到 Dashboard / Wizard UI。
