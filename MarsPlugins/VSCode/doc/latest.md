## Changes

- `ProcessInfo/Program.cs`
  - Added `jcmd -l`-based process discovery (already done in previous step).
  - Java process detection now accepts either Java modules or `jcmd` PID entries.
  - Display name prefers `jcmd` output when available.

- `src/processInfo.ts`
  - `findProcessInfoExe()` now selects the newest `ProcessInfo` binary by file modified time.
    - This avoids accidentally using stale `Release` build when newer `Debug` exists.
  - Added latest process cache file:
    - `scanedfiles/processes-latest.json`
  - On successful process scan, writes latest cache.
  - If `ProcessInfo` is missing/fails/exits non-zero, falls back to latest cache.

- `ProcessInfo/Program.cs` + extension UI
  - Added process source flag: `source = jcmd | fallback`.
  - WebSocket response now includes `source`.
  - Dropdown/QuickPick now shows source marker (e.g. `[jcmd]`) for each process.

- `src/panelProvider.ts` (Phase #2 started)
  - Added client-side license state loading (`scanedfiles/license.latest.json`).
  - Default mode is `TRIAL_LIMITED` if no license file exists.
  - Enforced replay policy:
    - within first 7 days: replay unrestricted
    - after 7 days: replay max 10 steps
  - Added UI warning + panel log when replay is blocked by license policy.

- `license-server/server.js` + `license-server/README.md` (Phase #4 started)
  - Added minimal endpoints:
    - `GET /v1/license/client-state`
    - `GET /v1/license/policy`
    - `GET /v1/license/declaration?lang=en|zh`
  - Added declaration payload (EN/ZH) for direct client download.
  - Added TEST pool control endpoint:
    - `POST /v1/license/test/claim` (admin)
    - region limited to `US` / `CN`, each max 200 slots.
  - `policy` + `client-state` now include test pool stats.
  - README endpoint list updated.

- `src/panelProvider.ts` (Phase #4 client integration)
  - Added periodic server sync before replay checks.
  - Client now pulls `client-state` and writes `scanedfiles/license.latest.json`.
  - Client now pulls `declaration` and writes `scanedfiles/license.declaration.latest.txt`.
  - If server unavailable, gracefully falls back to local latest cache.

- `src/panelProvider.ts` + `src/panel.html` (Ops-ready visibility)
  - Added toolbar license status badge (type/region/price).
  - Includes tooltip details: trial days, replay limit after trial, US/CN test pool remaining.
  - Panel init (`ping`) now forces one license sync and pushes status to UI.

- `doc/USER_GUIDE_zh.md` + `doc/USER_GUIDE_en.md` (Phase #3 completed)
  - Added complete release user guides in Chinese and English.
  - Covers install/build, scan/record/replay, keyword behavior, license rules, pricing, test pool, troubleshooting, diagnostics.
  - Added guide links in root `README.md`.

- `doc/RELEASE_CHECKLIST.md`
  - Added publish-ready checklist covering build, regression, license policy, server checks, docs, diagnostics, and final release steps.

- `doc/README_zh.md` + `README.md`
  - Added explicit License section (types, trial limit policy, pricing, test pool, minimal server endpoints, local synced files).

- `license-server/server.js` (admin UI)
  - Added simple management page: `GET /admin`.
  - Added admin APIs for operations visibility:
    - `GET /v1/admin/stats`
    - `GET /v1/admin/revocations`
    - `GET /v1/admin/query?q=...`
  - Supports displaying revocation total/list and query management (email/customerRef/licenseId based).
  - Upgraded admin to login + two-pane layout:
    - Login: `POST /v1/admin/login`
    - Left pane: summary by license type + searchable/filterable list
    - Right pane: selected license details (issuedAt, email, id, region, etc.)
  - Added `GET /v1/admin/licenses` for structured list/query data.
  - Added issued license persistence (`data/issued-licenses.json`) for admin listing.
  - Added per-license basic operations in admin detail pane:
    - `Renew` (extend expiry by days)
    - `Revoke` (mark as revoked)
  - Added backend action endpoint:
    - `POST /v1/admin/license/action` with `{ rowId, action, days }`.
  - Added Zelle mode end-to-end:
    - User side: `GET /zelle`, `POST /v1/zelle/order/create`, `POST /v1/zelle/order/proof`,
      `GET /v1/zelle/order/status`, `GET /v1/zelle/order/license`.
    - Server side: unique order ID generated by license server and persisted in `data/zelle-orders.json`.
    - Admin side: Zelle orders list + approve/reject actions in `/admin`; APIs `/v1/admin/zelle/orders` and `/v1/admin/zelle/action`.
    - Client side (extension panel): added `Pay`, `Fetch`, `Import Lic` actions.
  - Switched to Stripe payment mode for paid licenses:
    - User side: `/stripe` payment page and Stripe Checkout redirect flow.
    - Immediate permission path: payment success triggers `/v1/stripe/session/finalize` (plus `/v1/stripe/webhook` fallback).
    - Client side fetch now uses `/v1/stripe/order/license` by orderId+email.
    - Admin side can list and manually finalize Stripe orders via `/v1/admin/stripe/orders` and `/v1/admin/stripe/finalize`.
