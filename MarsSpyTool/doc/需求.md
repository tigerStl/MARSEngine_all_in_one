# MarsSpyTool — Finder 与 Web 自动化联动需求

## 1. 背景

用户在 **FinderButton**（`x:Name="FinderButton"`）上使用 **按下并拖放、在目标窗口上释放** 的方式拾取对象。释放时需识别鼠标下的 **窗口句柄** 与 **进程**；当目标为 **Web 浏览器** 时，应调用 **MARS.WebAutomation** 工作台完成页面信息与对象树的展示，并在树中定位到与拾取点语义最接近的节点。

## 2. 功能需求

### 2.1 Finder 拖放释放（Web）

- 触发条件：当前工具模式为 **查找对象**（`_find_obj`，即 Finder 十字准星流程），且在 `mouseLeftButtonUpImp` 中已获得有效 `hwnd`、`pid`、目标 `Process`。
- 当判定为 **Web 浏览器进程/窗口**（见 3.1）时：
  1. 调用 **MARS.WebAutomation** 打开工作台（独立 STA 线程 + `Application.Run`，不阻塞 MarsSpyTool 主 UI）。
  2. **第一个 Tab（Target page）**：根据已连接的 Playwright 页面填充 **URL** 与 **URL 解析**（Scheme / Host / Port / Path / Query）。
  3. **第二个 Tab（Objects）**：切换到该 Tab，拉取当前页 **对象树**，在右侧 **Grid** 展示选中节点属性。
  4. **树中定位**：根据 Spy 侧在释放点取得的 **UI Automation** 信息（如 `Name`、`AutomationId`、`ClassName`）与树节点 `DisplayName` / `LocatorHint` 做 **模糊匹配**，选中得分最高的节点并 `EnsureVisible`。

### 2.2 浏览器连接策略（MARS.WebAutomation）

- **优先**：通过 **Chrome DevTools Protocol** 连接本机常见调试端口（如 `http://127.0.0.1:9222`、`http://127.0.0.1:9223`），以便使用用户已打开的 Chromium/Edge 页面。
- **若 CDP 不可用**：回退为 **启动新的 Chromium** 实例（沿用 Settings 中的无头/通道等），用户可在首 Tab 自行导航；对象树在页面可用后刷新。

## 3. Web 判定规则（MarsSpyTool）

在不修改 `MarsProcessModule.GetTargetTypeFromProcessModule` 的前提下，于 MarsSpyTool 内使用启发式：

- 进程名包含（不区分大小写）：`chrome`、`msedge`、`firefox`、`iexplore`、`brave`、`opera`、`vivaldi`、`webkit` 等。
- 或窗口类名包含：`Chrome_Widget`，或为 `MozillaWindowClass` 等典型浏览器类名。

满足其一即视为 Web，进入 2.1 流程。

## 4. 实现约束（与 MarsSpyTool 的兼容性）

- **不得破坏**原有 `mouseLeftButtonUpImp` 中已有算法与分支逻辑。
- 仅在 `mouseLeftButtonUpImp` 的 `try` 块内、在取得 `Process p` 且排除本进程之后，**增加独立 `if` 块**：条件成立则 **处理 Web 联动并 `return`**；否则 **完全走原有代码路径**（与修改前行为一致）。

## 5. 依赖

- MarsSpyTool 工程增加对 **MARS.WebAutomation** 的项目引用。
- MARS.WebAutomation 提供对外 API：`WebAutomationApp.ShowWorkbenchForWebSpy(WebSpyPickContext)`（及上下文类型定义）。

## 6. 非目标（后续可迭代）

- 未开启 `--remote-debugging-port` 时，CDP 连接失败属预期，以回退启动新浏览器为准。
- 屏幕坐标到页面内 DOM 坐标的精确映射（多显示器、高 DPI、浏览器非客户区）可在后续版本加强。
